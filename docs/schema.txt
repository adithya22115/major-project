MediCycle - Backend Schema & Architecture Document
Project: MediCycle - Smart Medicine Donation & Redistribution Platform
Version: 1.1

1. Backend Architecture

Presentation Layer (Controllers)
        |
Business Layer (Services)
        |
Persistence Layer (Repositories)
        |
PostgreSQL Database

3. Database Tables

users
  id (BIGSERIAL PK)
  name (VARCHAR NOT NULL)
  email (VARCHAR NOT NULL UNIQUE)
  phone (VARCHAR)
  password (VARCHAR NOT NULL)
  role_id (BIGINT FK -> roles.id NOT NULL)
  address (VARCHAR)
  city (VARCHAR)
  state (VARCHAR)
  pincode (VARCHAR) -- Used for location-based medicine search and availability
  is_verified (BOOLEAN DEFAULT FALSE)
  created_at (TIMESTAMP)
  updated_at (TIMESTAMP)

roles
  id (BIGSERIAL PK)
  role_name (VARCHAR NOT NULL UNIQUE) -- DONOR, RECIPIENT, PHARMACY, ADMIN

medicines
  id (BIGSERIAL PK)
  medicine_name (VARCHAR NOT NULL)
  manufacturer (VARCHAR)
  category (VARCHAR)
  dosage (VARCHAR)
  description (VARCHAR)
  requires_prescription (BOOLEAN DEFAULT FALSE)

medicine_donations
  id (BIGSERIAL PK)
  donor_id (BIGINT FK -> users.id NOT NULL)
  medicine_id (BIGINT FK -> medicines.id NOT NULL)
  quantity (INT NOT NULL)
  batch_number (VARCHAR)
  manufacture_date (DATE)
  expiry_date (DATE)
  item_condition (VARCHAR) -- renamed from 'condition' (SQL reserved word)
  status (VARCHAR DEFAULT 'PENDING') -- PENDING, UNDER_REVIEW, APPROVED, REJECTED, DISTRIBUTED, EXPIRED
  remarks (VARCHAR)
  created_at (TIMESTAMP)

medicine_images
  id (BIGSERIAL PK)
  donation_id (BIGINT FK -> medicine_donations.id NOT NULL)
  image_url (VARCHAR NOT NULL)
  image_type (VARCHAR)

prescriptions
  id (BIGSERIAL PK)
  user_id (BIGINT FK -> users.id NOT NULL)
  doctor_name (VARCHAR)
  hospital_name (VARCHAR)
  file_url (VARCHAR)
  issued_date (DATE)

verification
  id (BIGSERIAL PK)
  donation_id (BIGINT FK -> medicine_donations.id NOT NULL)
  verified_by_id (BIGINT FK -> users.id NOT NULL)
  verification_date (TIMESTAMP)
  result (VARCHAR) -- APPROVED, REJECTED
  remarks (VARCHAR)

inventory
  id (BIGSERIAL PK)
  medicine_id (BIGINT FK -> medicines.id NOT NULL UNIQUE)
  available_quantity (INT DEFAULT 0)
  reserved_quantity (INT DEFAULT 0)
  distributed_quantity (INT DEFAULT 0)
  expired_quantity (INT DEFAULT 0)
  updated_at (TIMESTAMP)

medicine_requests
  id (BIGSERIAL PK)
  recipient_id (BIGINT FK -> users.id NOT NULL)
  medicine_id (BIGINT FK -> medicines.id NOT NULL)
  requested_quantity (INT NOT NULL)
  prescription_id (BIGINT FK -> prescriptions.id)
  status (VARCHAR DEFAULT 'PENDING') -- PENDING, APPROVED, REJECTED, COMPLETED
  approved_by_id (BIGINT FK -> users.id)
  created_at (TIMESTAMP)

notifications
  id (BIGSERIAL PK)
  user_id (BIGINT FK -> users.id NOT NULL)
  title (VARCHAR NOT NULL)
  message (VARCHAR(1000))
  type (VARCHAR)
  is_read (BOOLEAN DEFAULT FALSE)
  created_at (TIMESTAMP)

audit_logs
  id (BIGSERIAL PK)
  user_id (BIGINT FK -> users.id) -- nullable for system actions
  action (VARCHAR NOT NULL)
  entity_name (VARCHAR)
  entity_id (BIGINT)
  timestamp (TIMESTAMP)

verification_tokens (NEW - Email Verification)
  id (BIGSERIAL PK)
  token (VARCHAR NOT NULL UNIQUE)
  user_id (BIGINT FK -> users.id NOT NULL)
  expires_at (TIMESTAMP NOT NULL)
  used_at (TIMESTAMP)

4. Entity Relationships

Users (1) ---- (M) Medicine Donations
Users (1) ---- (M) Medicine Requests
Users (1) ---- (M) Notifications
Users (1) ---- (M) Audit Logs
Users (1) ---- (M) Verification Tokens
Medicines (1) ---- (M) Medicine Donations
Medicines (1) ---- (1) Inventory
Medicine Donations (1) ---- (M) Medicine Images
Medicine Donations (1) ---- (M) Verification
Medicine Requests (M) ---- (1) Prescriptions (FK: prescription_id on medicine_requests)

9. API Modules

/api/auth          - Authentication (register, login, verify email)
/api/users         - User profile (get, update, change password)
/api/medicines     - Medicine catalog
/api/donations     - Donation management
/api/verification  - Donation verification
/api/inventory     - Inventory tracking
/api/requests      - Medicine requests
/api/notifications - User notifications
/api/admin         - Admin dashboard & management

10. Security Flow

Login -> JWT Generation -> Client stores token -> Token sent with each request ->
JWT Filter -> Spring Security -> Role Authorization -> Controller
